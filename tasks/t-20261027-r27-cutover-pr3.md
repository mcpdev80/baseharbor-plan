## Exact output before a PR
Coordinator publishes a bounded diff identifying the completion workflow/event, check name, expected GitHub App, exact PR candidate association, any branch/ruleset migration and ordinary revert path. Verify actual current settings rather than repeating the old unverified claim that no policy edit is needed.

The final completion signal must run after durable approval publication. It cannot wait for post-run evidence from inside the same producer workflow whose success triggers that writer. It cannot let unapproved live verification or an older/different PR candidate satisfy the required check. Choose one bounded completion path, not a generic status framework or second evidence authority.

## Acceptance

Legacy enforcement stays until the reviewed replacement is active; explicit Owner cutover approval, actual selected checks and rollback validation are recorded. No full release matrix or unrelated trigger overhaul.
