# Draft: v0.4.27 trusted CI evidence archive contract

Status: **proposed, not accepted**. Scope: design-only on the isolated planning branch while v0.4.26 remains in release qualification. This does not activate or replace existing CI trust owners.

## Boundary and owners

1. **Untrusted producer:** ordinary PR jobs (including forks) run selected tests and upload bounded job artifacts using the normal Actions artifact mechanism. No write credentials for the planning repository; no secrets in payloads.
2. **Trusted collector/publisher:** a separately trusted post-run workflow obtains the completed run and exact attempt through GitHub's API, authenticates repository, workflow path/ref, event, head SHA, run/job/check identities, policy revision, outcomes and required artifacts. Never check out or execute untrusted PR code in the credential-bearing job. Treat artifact bytes as untrusted even when a workflow generated them.
3. **Planning archive:** `evidence/<release>/<candidate-id>/<run-id>-<attempt>/` is a bounded append-only *logical* namespace. The immutable identity includes source repository, candidate SHA, workflow identity, run ID and attempt; the directory slug is an encoding, not the authority. Write payload blobs first and the manifest last; never expose a manifest referencing incomplete blobs. Reject collisions with different content, permit byte-identical idempotent retries. Concurrency uses create-only writes and retry/rebase against current planning HEAD, never force-push or clobber another task edit.
4. **Read-only resolver:** look up by the complete identity and expected manifest digest; validate canonical path, size, schema, digest and referenced payload existence. Return typed not-found/incomplete/corrupt/ambiguous/unauthorized results. A resolved archive is **not** a green qualification.
5. **Trusted verifier/finalcheck:** independently authenticate the recorded run provenance and compare exact current candidate, integration SHA set, required checks, policy revision and successful outcomes. Reuse existing planner/executor/finalcheck authorities; no new bypass or fallback to an older green after a newer relevant failure.
6. **Planning linker:** after successful archive publication, associate the manifest digest and immutable locator with the matching task and PR via a conflict-safe planning update. If the link fails, retry without republishing or overwriting the proof. Do not mark the task accepted or merge the PR merely because evidence was archived.

## Minimal proposed manifest v1

Canonical UTF-8 JSON (deterministic key order and compact encoding) with explicit version and no extra keys. Example placeholders are illustrative, not authentic evidence:

**Schema decisions to settle before acceptance:** canonical candidate ID encoding; trusted GitHub run/job attestation strategy (the JSON fields above are *claims* until independently authenticated); explicit policy fingerprint and runner/input equivalence for reusable checks; required vs optional payload inventory; exact maximum payload and total archive sizes; approved MIME types; redaction allowlist; public/private archive visibility; timestamp source; and whether an existing finalcheck receipt supplies some fields. The example workflow path is illustrative, not a claim that this workflow exists. Do not duplicate existing receipts if a verified one can be referenced by digest.

A manifest checksum is the SHA-256 of its canonical raw bytes, supplied externally as the resolver's expected digest. A manifest MUST NOT claim its own digest. SHA-256 detects mutation but does not authenticate authorship; the trusted GitHub origin and publisher authorization must be independently established.

## Publication and failure semantics

- **Prepared:** collector validates all selected artifacts, byte counts, MIME types, safe filenames, exact expected check IDs and secret-redaction allowlist in memory or isolated scratch space.
- **Staged:** publisher creates uniquely named blobs on an isolated branch. Existing identical blobs are idempotent; conflicting paths fail. A crash here leaves unreferenced blobs that cannot qualify.
- **Committed:** publisher creates manifest last, only after verifying each committed blob hash. Publishing a manifest is not approval.
- **Linked:** a separate retryable planning update associates the manifest digest with the task and PR, preserving concurrent edits. Missing link is a visible actionable pending state, not fabricated acceptance.
- **Verified:** current trusted finalcheck independently resolves and authenticates everything. Missing artifact, incomplete archive, expired run with no already archived proof, unknown check, changed SHA/policy, redaction failure or archive write failure cannot become green.
- **Garbage collection:** only unreferenced incomplete staging is eligible under a documented bounded retention policy; never silently delete published manifest records. Git is not WORM; external backup and recovery are separate operational requirements.

## Minimal negative regression matrix

| Case | Required result |
| --- | --- |
| Fork PR attempts to access publisher token | No token exposed; publisher runs in trusted context only |
| Two runs publish concurrently | Both retained; no force-push, no lost planning updates |
| Same identity retried with identical bytes | Idempotent, single logical record |
| Same identity retried with different payload | Conflict, no overwrite |
| Crash after blobs but before manifest | Incomplete, not qualified |
| Manifest missing payload or bad digest | Corrupt/incomplete, fail closed |
| Source/integration SHA or policy changes | Archived but not qualified for new candidate |
| Wrong run attempt, workflow or job/check ID | Unauthorized/stale, fail closed |
| Cancelled/failed check or newer relevant failure | Not green, no stale fallback |
| Expired Actions artifact / deleted PR branch | Existing archive still resolves; qualification rechecks current predicates |
| Secrets or unsupported binary in payload | Reject before archive publication |
| Task-link conflict | Retry from latest planning HEAD without clobbering |
| Untrusted archive author | Resolve may read, verifier rejects unauthenticated origin |

## Cheap preflight, not release automation

Before dispatching expensive gates, invoke the existing `scripts/ecosystem_release_pins.py` validation for immutable Core/Demo/Console/Connector candidates; check declared release notes, required artifacts and candidate inputs. Emit machine-readable `code`, `repository`, `requirement`, `next_action` plus a concise human diagnostic. Do not modify pins, infer missing SHAs, grant review or trigger a full matrix from this preflight. A separate later task may propose the ordered consumer freeze.

## Definition of contributor success

A normal human, Codeman, Codex or fork contributor creates one PR and gets selected CI, archived proof, task/PR link and a clear qualified/pending/failed status automatically. No special agent commands, manual evidence JSON, copying URLs, or manual SHA chains. Publication, verification and merge remain separate authorities.
