# v0.4.27 zero-touch contributor baseline (2026-10-23)

Scope: read-only source inspection of `mcpdev80/baseharbor@develop` and planning contracts. This is research, not accepted runtime evidence or permission to modify v0.4.26.

## Confirmed reusable owners

- `.github/workflows/pre-release.yml` already accepts `only_gates` for selected release checks; its `source` job resolves candidates before the expensive runtime matrix.
- `scripts/ecosystem_release_pins.py` already validates an exact four-repository Core -> Demo -> Console -> Connector DAG, 40-character immutable SHAs and candidate consistency. Reuse this resolver; do not build a second source-of-truth.
- `scripts/private_consumer_evidence.py` authenticates private consumer evidence origin, workflow, SHA and gate identity. This is a trust verifier, not the new durable plan-archive publisher.
- `docs/development/v0.4.22-evidence-resume.md` documents exact-input reuse and archive validation. Reuse the existing policy/receipt semantics; never treat cancelled checks as green.
- `AGENTS.md` and `docs/DEVELOPMENT_GUIDELINES.md` already specify focused CI, single ownership and release safeguards.

## Gaps to implement after accepted contract

1. A trusted post-run publisher must automatically collect bounded, sanitized CI artifacts, write collision-safe immutable-named plan archive records, and link task/PR without exposing credentials to fork code.
2. A read-only resolver must retrieve the archived record even when the source branch or Actions artifact is gone. Its successful lookup alone is not qualification.
3. A verifier must compare archive checksums, source/integration SHA, run attempt, provenance and current trusted check policy; reuse existing finalcheck authorities rather than weakening them.
4. A cheap preflight should run the existing pin resolver and check candidate/docs prerequisites before expensive matrix dispatch. It must produce an actionable missing-input diagnostic; it must not invent a consumer SHA or mutate a release pin.
5. Consumer-freeze automation is a distinct future scoped task: it may propose/review immutable Console and Connector candidates in dependency order; no automatic approval or silent publication.

## Minimal acceptance journey

A human contributor, Codeman worker, Codex session or external fork opens an ordinary PR. The selected checks run; trusted post-run automation creates, archives, verifies and links the bounded evidence. The contributor sees PASS or a concrete reason/next action, without manual JSON, archive upload, copied evidence links or role-specific handoff. Concurrent planning edits must be preserved.

## Safety boundary

This branch is planning-only. Do not edit `baseharbor@develop`, v0.4.26 workflow, consumer pins, active product branches or release candidate. Do not claim evidence implementation is complete. v0.4.27 integration waits for v0.4.26 Verify and accepted startup prerequisites.
