## Befund F1 — sameProviderInstanceAuthority omits authority-bearing fields

Location: `internal/application/provider_consent_authority.go:495-511`.
`sameProviderInstanceAuthority` compares ID, ProviderID, ProviderVersion, ProviderProtocol, Provider.Kind, Capabilities, Scope, SharingBoundary, Ownership, OwnerApplicationID — but NOT `Reference` and NOT `OwnerEnvironment`.
Both fields exist on the type (`internal/capability/registry.go:42-45`):
- `OwnerApplicationID string json:"owner_application_id,omitempty"` (:42)
- `OwnerApplication string json:"owner_application,omitempty"` (:43)
- `OwnerEnvironment string json:"owner_environment,omitempty"` (:44)
- `Reference string json:"reference,omitempty"` (:45)
`Reference` resolves external-scoped providers (`registry.go:127-151`); `OwnerEnvironment` constrains binding (`registry.go:225-230`) and registry validation (`registry.go:434-439`). Two instances that differ only in `Reference` or `OwnerEnvironment` currently compare as the same authority — the consent fold misses a real change.
Fix: add `a.Reference == b.Reference &&` and `a.OwnerEnvironment == b.OwnerEnvironment` in the same return chain; update the comment to name them.
Decision on `OwnerApplication`: record whether it participates.

## Befund F2 — equalProviderCapabilities multiset hole

Location: `internal/application/provider_consent_authority.go:549-566`.
`equalProviderCapabilities` checks `len(a) != len(b) -> false`, then membership of each left value in the set built from b. For `a=[x,x]` and `b=[x,y]`: lengths equal (2), every element of `a` is in `{x,y}` -> returns TRUE although the multisets differ.
Fix: compare per-kind counts via a `map[capability.Kind]int` accumulator (bump on b, decrement on a; any non-zero at the end -> false). This detects duplicate entries masking a missing/different capability. Choice justified in akte.
