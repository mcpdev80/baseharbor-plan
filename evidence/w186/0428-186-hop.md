## Explicit decision (Owner directive — probe = the instrument)

Owner scope review @ head 5f000fb: the fail-closed fix (dropping the static `hostProviderMetricsNativeVerified` derivation) set `verified` to **permanently unreachable** (perses.go ~:215 "this state can never be produced here"). That is the wrong terminal design: card 0428-186 acceptance item 2 requires the 0428-078 positive case (`status --json identity_dashboard_eligible=true`) to be reachable **by test without touching the verified-only predicate**, and #1650's `IdentityDashboardEligible=true` is derived FROM that `verified` surface (app_status_result.go). If `verified` can never be true, #1650's eligible path is dead and the feature cannot ship.

**Decision: implement a genuine per-target reachability probe as the instrument.**

- **What the instrument is:** the established `persesInfraProbe.querySeries(ctx, endpoint, query) (bool, error)` seam in `internal/metrics/perses_infra_dashboards.go`. `querySeries` performs a real HTTP round trip (`queryUp`) against the **per-target materialized Prometheus endpoint** (`persesPrometheusDatasourceEndpoint(m)` → `ProviderEndpoint(files)`), keyed on the deployment's own authorized sources and metrics policy. This is exactly "target/provider selection in, answer observed out". It already gates the infra-dashboard builder as **fail-closed** in `buildInfraWithProbe`: `present == true` → verified, `present == false` / probe error → visible gap (fail toward missing, never an optimistic true).
- **Why it is the correct instrument:** (1) it is NOT the static catalog scan CODEX-REVIEW rejected — `ReferenceIntegrations()` has no target/provider input, whereas `querySeries` resolves the endpoint for THIS manifest's selected, pinned Perses surface and observes the live Prometheus backend answer; (2) it answers a real per-selection question ("does this selection's backend answer?"), so a silent / absent / unpinned / denied target yields a clean `false` (fail-closed → configured_unverified) and an answering target yields `true` (→ verified); (3) it reuses existing, reviewed code and the existing `httpClientSeriesProbe` production adapter — no invented probe, no `scripts/**`, one branch.
- **Where it runs:** `PersesStatusNow(selected bool)` is a *pure manifest→status mapper* in the capability package with no manifest/ctx, so it cannot itself run a probe. The probe is inherently a deployment-STATE question (materialized endpoint + real answer), so the status entry point that runs the probe is added in the `metrics` package (`BuildPersesInfraDashboardWithProbe`-family fail-closed verdict → three-state mapping) and called from the two status call sites that hold the manifest: `cmd/baha/app_status_result.go:309` and `internal/application/management_ui.go:466`. `PersesStatusNow(selected)` remains the pure fail-closed mapper used by `perses_lifecycle.go`.
- **Terminal contract (what the state machine now does):**
  - unselected → `not_configured`
  - selected + unpinned/invalid release → `not_configured` (fail-closed)
  - selected + pinned + **real probe answers** → `verified` (eligible reachable)
  - selected + pinned + **silent / absent / denied / probe error** → `configured_unverified` (never a static/literal true)
- **verified-only predicate:** untouched (owner-closed for 0428-078).
