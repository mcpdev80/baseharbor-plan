## CI selection / duplicate execution audit — 2026-11-07

Examined live Core `develop` workflow definitions, the PR planner/runner and open PRs #1408/#1409.

1. **Verified duplicate:** `actionlint` runs in the always-on `workflow_policy`, the always-on `pr_focused`, and often as the selected `ci-actionlint` validation. `test_pr_gate_plan.py` and `receipt-execution-tests` likewise run both always-on and via their selected validations on CI changes. **Correction submitted:** [PR #1410](https://github.com/mcpdev80/baseharbor/pull/1410) removes the redundant *always-on* invocations. The receipt contract regression had an old requirement to invoke receipts twice and was updated to verify the trusted selected validation job instead. Native/Release suites unchanged; PR must pass exact-head CI before merging.
2. **Verified package overlap:** a changed `cmd/baha/*_test.go` may select both `cli-package-tests` (full `go test ./cmd/baha`) and `cli-guided-tests` (subset `-run ^TestGuided`) in the same PR. Distinct check IDs do not prevent repeated Go executions. **Correction submitted:** [PR #1411](https://github.com/mcpdev80/baseharbor/pull/1411) deduplicates only the Guided subset when full CLI package execution is already selected at the same candidate, retaining Guided alone otherwise, plus format/vet/build and fail-closed planner behavior. Selection regression cases are included; PR CI must pass exact head before merge.
3. **Conservative unknown-impact fallback:** the selector can run broad `go test ./...`, `go vet ./...`, `go build ./...` plus narrower checks. Keep the fail-closed safety fallback for now: it is expensive, but not safe to discard until the missing coverage map has been validated.
4. **PR versus develop:** PR planners set `runtime_required=false` and `public_contracts_required=false` as an intentional non-blocking cross-repo boundary. It follows that a green PR is *not* proof of native Docker/Podman. Ordinary `develop` pushes have no central blanket integration runner; runtime workflows must be explicitly selected or dispatched.
5. **Native dependency path selection:** [PR #1408](https://github.com/mcpdev80/baseharbor/pull/1408) originally selected stack/Compose changes but omitted `openbao_runtime_prepare.go`, `openbao_storage.go`, and `bootstrap_postgres_tls.go`. These paths and focused regression expectations were added. This gate checks the selected PostgreSQL/OpenBao graph only, not an unconditional Keycloak/Core bundle. **Pending latest-head PR CI and post-merge real native tests.**
6. **Remote Target selection:** [PR #1409](https://github.com/mcpdev80/baseharbor/pull/1409) passes its latest-head PR CI; the narrow Docker/Podman developer-local fallback rejection is correctly selected by existing `cli-package-tests` and does not start a native container runtime. Real remote-host networking/authorization still belongs to existing feature acceptance cards.
7. **Same Go test name can be deliberate:** `targeted-integration.yml` invokes `TestCorelessFreshWorkloadRuntimeLifecycle` in a default local workload step and separately in an explicitly tagged local-prod authorization step with `BASEHARBOR_CORELESS_ENVIRONMENT=prod`. These exercise distinct environment semantics; do not deduplicate merely by test name without examining environment and assertion intent.
8. **Remaining release/pre-release issue:** gate catalog registration for unreleased v0.4.27 and the absence of exact-run proof for Core/Demo/Console/Connector integration remain unclosed. No release/tag/main promotion authorized.

Rule: deduplicate by **(test + runtime + environment/fixture + source SHA + required assertion)**, not by test name or gate ID alone.
