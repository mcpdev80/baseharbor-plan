## Reality witnesses: the two selectors (built on r2 table, de53246585 source)

- `extractApplicationEnvironment(args, command)` (`cmd/baha/app_context.go:597`) parses BOTH flags out of the positional list:
  - `-e`/`--environment` (`app_context.go:603-621`) captures an **environment value** (e.g. `prod`); a second conflicting value errors (`conflicting environment selections`, line 610/619). It never carries identity.
  - `--uuid`/`--uuid=` (`app_context.go:622-632`) is consumed here and stripped from positionals; the bare value is left for `extractApplicationUUID`.
- `extractApplicationUUID(args)` (`cmd/baha/app_context.go:646`) doc comment (lines 640-645): "It is the unambiguous identity for a name-colliding deployment that **no `-e` value can disambiguate**." This is the authoritative statement that the two selectors are NOT interchangeable: `-e` picks an environment, `--uuid` picks an identity.
- The `--uuid` selector is stripped BEFORE the one-NAME limit (`withoutUUIDSelector`, `app_context.go:152`), so a uuid selector is satisfied by identity alone, without a positional NAME.
- `-e/--environment` without a NAME: the environment value is optional metadata; it never substitutes for a NAME where a NAME is required, and it is not an identity selector.
- `app env` (`parseAppEnvArgs`, `cmd/baha/app_env.go:50-83`) rejects any leading `-` token (`app_env.go:66` → `unknown option`), so BOTH `--uuid` AND `-e/--environment` are non-executable there — exactly as the r2 table records (`app_env.go:66`, Usage line 21).
- **The r2 table is unchanged on this head** — the per-subcommand selector reality is internally consistent; only the DOC wording was wrong. The r3 correction therefore carries no behavior change.
