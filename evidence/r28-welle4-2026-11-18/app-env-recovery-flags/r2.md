## Reality witnesses: the selector path (built from 7aa8b01e9 source)

- `resolveApplication` → `resolveApplicationEnvironment(ctx, _store, args, command, environment, selectedDeploymentID...)` (`cmd/baha/app_context.go:110`).
- `extractApplicationEnvironment(args, command)` (`cmd/baha/app_context.go:597`) consumes the `--uuid`/`--environment` FLAGS and removes them from the positional list; the bare `--uuid` VALUE is left for `extractApplicationUUID`.
- `extractApplicationUUID(args)` (`cmd/baha/app_context.go:646`) pulls the `--uuid <id>` selector out.
- `nameArgs := withoutUUIDSelector(filtered)` (`cmd/baha/app_context.go:152`) then enforces the one-NAME limit (`if len(nameArgs) > 1`, line 153). **The `--uuid` selector is stripped BEFORE the one-NAME limit** (comment lines 135-144). So `--uuid` alone, without a positional NAME, passes the limit check.
- `resolveRegisteredApplication(..., selectionUUID)` (`cmd/baha/app_context.go:360`) routes the `--uuid` selector directly at the registry seam (`if strings.TrimSpace(deploymentUUID) != ""`, line 368), bypassing the name filter.

## Reviewer objection (r2) confirmed against source + regression

- The r1 akte (`fix-1.md:29`) and the original passage claimed the `--uuid` selector "needs the positional NAME in front of it" for every identity-reading command. This is FALSE on this head.
- Proof, regression `app_registry_poison_recovery_test.go`: line 195 `resolveApplication(t.Context(), application.Store{}, []string{"--uuid", twinIDs[0]}, "status")` — `status` addressed by `--uuid` **without** NAME, asserted to resolve to one twin (lines 196-208). The `--uuid` repair path the guard advertises (`baha app <cmd> --uuid <id>`) is NAME-free.
- Proof, `app destroy` repair: test uses `--uuid <id> --full-reset --yes` with no NAME (`app_registry_poison_recovery_test.go:339,508`).
- The correct statement: every identity-reading subcommand accepts `--uuid` WITHOUT a NAME; `app plan` is the only reader that refuses `--uuid` on a remote target. `app env` is the only subcommand that rejects `--uuid`/`-e` outright.
