## Seven SHA-exact counterprobes

1. **Claims originate in verified signed token — PASS for extraction; production flow is incomplete.** `internal/auth/oidc.go:105-138` calls the configured OIDC verifier before `token.Claims` and only then copies group/app-role values to the Principal. I found no request-header/body claim extraction in the changed path. However, the authorization path has no production MembershipProvider caller (repo search finds `WithMembershipProvider` only in its definition and tests), so the new claim-to-membership behavior is not connected to a live request path.

2. **Missing/empty role fails closed — FAIL.** With a MembershipProvider installed, an unresolved membership is denied at `internal/operatorauth/authorization.go:157-168` and `authorization_claims_test.go:83-108`. But the provider is optional (`context.go:62-75`); without one, a verified principal falls through to the generic authenticated allow at `authorization.go:127-130,195-204`. I ran a temporary, non-committed counterprobe using a verified `prod` Principal with no provider and no membership; `AuthorizeMachineOperation` returned `Allowed=true`. This violates “SSO login alone grants nothing” and is the primary fail-open finding.

3. **Two-team scope — PARTIAL, required feature-level regression absent.** `tenancy.Resolve` rejects memberships across `tenant-a` and `tenant-b` (`internal/tenancy/context.go:47-65`; existing `context_test.go:27-35`), so the shared resolver has a fail-closed ambiguity guard. The new team-auth tests use only one tenant (`authorization_claims_test.go:66-68,143-146`); there is no two-team test through `AuthorizeMachineOperation`, and no production provider is installed to bind claim sets to the selected team. The requested end-to-end isolation probe is therefore not demonstrated.

4. **Revoked claim/membership fails closed — PARTIAL / not proven.** If a provider is present and returns an error or no membership, authorization returns a policy denial (`authorization.go:157-168`). But there is no production provider/call site, no regression using the provider error field, and no test showing a revoked membership stops a subsequent operation. Existing EN/DE machine-http specs state group changes may not be revoked instantly during an issued token's lifetime (`docs/spec/machine-http-v1.md:39-40`, `docs/de/spec/machine-http-v1.md:39-40`); that bounded limitation does not prove the requested fail-closed revocation lookup.

5. **No token/secret in logs or journal — PASS for this implementation.** `OIDCVerifier.Verify` does not store the raw token in Principal; verification failures return the collapsed `ErrInvalidToken`. `Principal.String` includes only issuer and subject (`identity/principal.go:78-84`), and `TestOIDCVerifierStringDoesNotExposeClaims` covers claim leakage. Search found no caller logging `identity.JSON` or the raw token.

6. **Task write-set — FAIL.** The task reserves bounded auth/identity/authorization/operatorauth claim-policy work. The actual PR diff also adds four unrelated profile-codec files: `contracts/managementaccess/v1/store.go`, `store.golden.json`, `store_test.go`, and `store_testseams_test.go`. These are outside the card's write-set and have no documented dependency or ownership handoff in the task note. The remaining seven files are in the expected auth/policy area.
