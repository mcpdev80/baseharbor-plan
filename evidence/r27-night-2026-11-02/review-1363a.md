## Seven review points

1. **Secret-free export — FAIL.** `TestExportCarriesNoSecret` builds a typed record without any secret field/value and then searches its JSON for sentinel strings that were never set. I ran the production `ExportToContainer` path on the exact candidate after setting `Recipient` to `https://user:SECRET-CANARY@example.invalid`; export succeeded and serialized the credential canary (`credential_url_secret_rejected_or_excluded=false`, `secret_leaked=true`). This is possible because export does not validate/bind the recipient. `RecordWire` has no secret/ciphertext field; only the encryption descriptor is carried. A separate raw-JSON probe with `secret: SECRET-CANARY` excluded that unknown property only by silently dropping it (see point 3).
2. **Canonical import/export round trip — FAIL / unproven.** The tests check encode→decode validity, not import→export byte/order stability, and `Store` has no export-from-store operation. An independent golden fixture decode→encode comparison was not stable: timestamp moves from before `records` to after it (`golden_canonical_reencode=false`). The JSON encoder's struct order is deterministic, but the fixture and round-trip contract do not assert that canonical order.
3. **Unknown fields — FAIL.** `decodeContainer` calls `json.Unmarshal`, which silently ignores unknown fields. My exact-candidate probe with both `secret: SECRET-CANARY` and `future_field: UNKNOWN-CANARY` removed both without an error (`unknown_field_preserved=false`). The required policy is a typed error or explicit preservation; silent loss is neither.
4. **Schema/version and import binding — FAIL.** Container version is checked, and an export record version mismatch against the caller's `version` argument is rejected in the test. But record version is not validated against the canonical supported marker; passing the same arbitrary `/v99` as both argument and record is accepted by `ExportToContainer`, and `Store.Import` also accepts it when `NewStore` is opened with that version. More critically, `Import` calls `ValidateKindEnforcement` but does not run the JSON schema or bind expected installation/scope/recipient. The card's required before-write installation/scope guard is absent: an exact-candidate probe modified the golden record to empty `installation_id`, `recipient="foreign-credential://user:pass@remote"`, and `scope="bad scope"`; `Store.Import` returned success (`invalid_installation_recipient_scope_rejected=false`). The existing `TestImportWrongScopeRejectedBySchema` calls the schema validator directly and never exercises `Store.Import`.
5. **Write-set — PASS.** The exact PR diff is limited to the four new codec/store files in the reserved `contracts/managementaccess/v1` area; no unrelated paths are changed.
6. **Package tests/build/gofmt/vet — PASS locally; hosted selected checks have not run.** From an archive of exact SHA `0eb8f231`: `GOCACHE=/tmp/codex-review-1363a-gocache go test ./contracts/managementaccess/v1` passed; `go vet ./contracts/managementaccess/v1` passed; `go build -buildvcs=false ./contracts/managementaccess/v1` passed; `gofmt -d` on all changed Go files produced no output. GitHub run `41833092179`: Workflow policy and PR · Source format SUCCESS; 14 jobs SKIPPED, including PR Selected Checks. This is consistent with current `.github/workflows/ci.yml` draft policy (the selected jobs require `draft == false`); it is not evidence of those selected tests passing.
7. **EN/DE docs and spec — FAIL / incomplete for the new model.** The English and German `credential-access-v1` specs describe credential-export as an encrypted local credential payload, but this codec's `RecordWire` contains only the algorithm/encrypted/nonce descriptor and no ciphertext. Neither language documents the new `baseharbor.profile-container/v1` outer shape (`dest_path`, `timestamp`, `records`) or its unknown-field behavior. Clarify that this card exports metadata/envelope only (no ciphertext) and document matching EN/DE wire semantics, or extend the model and tests if carrying encrypted payload is intended.

## Verdict: REJECT

### REZEPT

- `contracts/managementaccess/v1/store.go`: validate every imported/exported record against the canonical record version and normative schema before writing; require an expected installation/recipient/scope/trust binding as an input to the store and reject mismatches before side effects. Reject credential-bearing URLs and other secret material in all serialized fields, including recipient and destination path. Do not rely on `ValidateKindEnforcement` as a schema or installation-binding check.
- `contracts/managementaccess/v1/store.go`: decode with unknown-field rejection (including nested records), or retain unknown values losslessly under a documented forward-compatibility rule. Add adversarial tests with an actual secret canary and an unknown future field; require either a typed rejection or lossless documented preservation, and assert no secret reaches exported bytes.
- Define the canonical container format and real import→export API/round trip. Pin field ordering/format and record ordering in a regression; make the golden fixture follow the canonical representation.
- Make transactional writes genuinely atomic and test a partial-write failure leaves no file/state behind. `Import` currently uses `os.WriteFile` directly and returns on its error without cleaning a possible partial destination. Test conflict-replace by verifying the previous record is actually replaced, not just that `Replaced == 1`.
- Update `docs/spec/credential-access-v1.md` and `docs/de/spec/credential-access-v1.md` together so payload/envelope semantics and the outer container schema exactly match the implemented model.
- Required recheck at corrected SHA: rerun the secret, unknown-field, bad-version, wrong-installation/recipient/scope, canonical round-trip, partial-write and conflict-replace probes; run package tests, build, vet and gofmt; mark the PR ready and observe the selected checks required by current CI before claiming those gates.
- Stop/reject if wrong installation/scope/version reaches a write, an unknown credential field is silently discarded, a secret appears in export, or round-trip/import behavior is not canonical and repeatable.
