## Keeper #1: stale-impact-consent (FIXED)

Root cause: revalidateApplicationProviderIntent (cmd/baha/application_provider_authorization.go) compared the re-resolved manifest against the execution resolved manifest with reflect.DeepEqual. The deployment-only, never-serialized providerPreferences projection is a *[]ProviderPreference pointer: nil means inherit, an explicit empty slice means automatic, and both mean the same thing. The resolve path that layers applied backend selections sets a non-nil empty projection; the repository re-resolve leaves it nil. reflect.DeepEqual distinguishes a nil pointer from an empty non-nil pointer, so an unchanged manifest was rejected as stale-impact-consent.

Empirical proof (docker, BASEHARBOR_ENV_DESTROY_ACCEPTANCE=1):
- Before fix: DIAG revalidate sel.prefsNil=true resolved.prefsNil=false deepEqual=false -> provider change: stale-impact-consent at env_destroy_integration_test.go:128.
- After fix: test progresses past :128; KEEP-destroy apply completes (retireRuntimePreservingData returns nil); :136 reads the retained record.

Fix (additive, production-side, two files):
- cmd/baha/application_provider_authorization.go: manifestIntentEqual(a,b) compares reflect.DeepEqual, then falls back to comparing each side against the other's CanonicalizeProviderPreferences() so nil-vs-empty compares equal. revalidateApplicationProviderIntent uses manifestIntentEqual instead of reflect.DeepEqual.
- internal/application/provider_preferences.go: ProviderPreferencesIsNil() and CanonicalizeProviderPreferences() (empty -> nil, preserving the never-serialized projection).

No fixture change. Build (go build ./...) and vet (go vet ./cmd/baha/ ./internal/application/) clean. Regression: internal/application provider-preferences + consent tests pass; cmd/baha revalidation/consent/authorization tests pass.
