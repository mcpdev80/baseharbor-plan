## Verdict

**REJECT** candidate `cd336cf734e36156ca7f1aef1ab78f449e8b56e2`.

The static host check is not safely integrated with the lifecycle executor. On an attached installation, the server holds the installation lifecycle lock for the entire server lifetime. Existing Core lifecycle work reacquires that same lock, so the management host blocks its own lifecycle operations. On a fresh root, the bootstrap path returns success without any lock and then proceeds to bind, allowing concurrent fresh servers to bind as writers. The context intended to pin the selected root is also not consumed by the executor or server.

## Mission checks

1. **One active writer on one durable root before bind — NOT SATISFIED.** `internal/coreinstallation/management_host.go:94-100` returns `(bootstrap=true, unlock=nil, err=nil)` for a missing root. `cmd/baha/serve.go:57-69` does not create/acquire a bootstrap ownership lock or stop startup on that result; it continues to `controlplaneruntime.Run`, which binds the server. Therefore two fresh processes can both pass the missing-root check and bind without exclusive ownership.

   For an existing installation, `cmd/baha/serve.go:58-60` defers unlock until the server exits. This is the same `AcquireLifecycleLock` used by Core update execution, e.g. `cmd/baha/update_core_native.go:430`. On Unix that lock uses `flock` on a separate open file descriptor (`internal/stableid/lock_unix.go:17`); an operation inside the long-running server cannot reacquire it while the host holds it. The management host would reject its own lifecycle operation as already active.

   In addition, `cmd/baha/serve.go:66` adds the host root to `startup` only after `newInstallationMachineExecutor(startup, store)` has captured the authority. The final call at line 69 still passes the original `ctx`. `managementHostAttachedRoot` is defined in `serve_management_host.go:27` but has no consumer in this candidate. The selected root therefore is not actually pinned through the executor/server path.

2. **Bootstrap versus attach and fail-closed — PARTIAL.** The code distinguishes missing-root bootstrap from valid-root attach and refuses foreign, unprotected, and already-locked roots. But bootstrap is not mutually exclusive and is treated as permission to bind without an owner lock, so the full fail-closed acceptance does not hold.

Do not hold a non-reentrant per-operation lifecycle lock across the server lifetime.
