## Blocking ownership flaw

The bootstrap and lifecycle locks are separate kernel locks and files: `.bootstrap.lock` and `.installation.lock` (`internal/stableid/lock.go`). `serveCommand` retains only the bootstrap lock on a fresh-root bootstrap path. Once that process provisions a valid installation, a competing `ManagementHost.Verify()` no longer treats the root as fresh: it loads the valid installation and acquires only the lifecycle lock. It does not contend on or check the bootstrap lock. The bootstrap-serving process does not hold the lifecycle lock. Thus a second management host can acquire lifecycle ownership while the first bootstrap server remains alive. The deferred unlock closes the pre-bind gap for two *fresh* roots, but it does not establish exclusive writer ownership for the server lifetime after provisioning.

## Required correction recipe

1. Make one ownership primitive cover the root continuously from fresh-root bootstrap through server lifetime and the valid-installation attach path. Ensure a process that sees a newly valid root cannot acquire competing ownership while the bootstrap server still owns it. Use an atomic/shared ownership protocol or an explicit safe lock handoff with no interval in which neither lock protects the root; do not rely on two independent lock files whose acquisition paths do not check one another. Keep the selected state root pinned through provisioning and the server.
2. Replace the current guard-only subprocess regression with an actual `serveCommand` integration regression. Start process A on a fresh root at listen address A, wait until it is demonstrably bound and serving, then start process B against the same root at a different listen address B. Assert B fails specifically for ownership, A remains reachable/serving, and repeat/assert the valid-root-after-provisioning case while A is alive. Distinct addresses must ensure a port collision cannot create a false refusal.
3. Add a focused `serveCommand` test where `managementHostForServe` returns a non-nil error and assert the command returns that error without starting the runtime. Preserve and test the intentional `(nil, nil)` no-host path.
4. Add causal mutation evidence against the actual production ownership transition/lock-lifetime line changed for this fix. Record SHA-256 hashes of the production file before mutation, under mutation, and after restoration; the new serve integration regression must be GREEN before mutation, RED under the mutation for the ownership failure, then GREEN after exact restoration. Do not substitute a mutation of `Verify()`'s pre-existing bootstrap guard.
5. Re-run the focused tests, build/vet and required hosted checks on the final exact PR head; record all terminal statuses. Keep the write set free of `.github/**` unless separately authorized and in scope.
