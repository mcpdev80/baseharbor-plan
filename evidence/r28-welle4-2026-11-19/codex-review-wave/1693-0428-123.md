## Blocking findings and recipe

1. **Target globs overlap for a valid application name.** `appTargetFileName` emits `<application>--<environment>--<source>.json` (`internal/metrics/prometheus_files.go:47-64`). `prometheus_render.go:198` sends `*--*--*.json` to `baseharbor-applications`, while `:225` sends `provider--*.json` to `baseharbor-providers`. Application name `provider` is valid under the slug rule and produces `provider--dev--api.json`, which matches both globs. The current duplicate regression uses `demo`, so it cannot expose this collision.
   - **Change:** make application target filenames and provider target patterns structurally disjoint (for example, reserve a distinct `application--` namespace and narrow the application glob, or narrow the provider glob to only provider-generated hash filenames); keep both target families readable by their intended jobs.
   - **Test:** add a valid application named `provider`; render targets and assert its source is selected exactly once by the application job and never by the provider job. Exercise the emitted Prometheus glob patterns, not only file-prefix classification.
   - **Stop:** do not accept while any valid application slug can make one target file match both job patterns.

2. **Stale application targets survive subsequent synchronization.** `syncProviderTargets` removes old `provider--` / `provider-secure--` files (`prometheus_files.go:66-81`), but application-class files are written under `<application>--<environment>--<source>.json` (`:125-162`) and are not pruned when absent from the next `ListMetrics` result. Since the applications job reads that filename class, a removed or no-longer-authorized environment source can remain scraped. The current dev/stage regression starts from an empty target directory, so it does not cover replacement of an existing projection.
   - **Change:** reconcile the application-target namespace on every sync: retain only filenames corresponding to the current selected application sources, without touching runtime-target files or unrelated state.
   - **Test:** in the same target directory, sync a stage source first, then sync only the dev result; assert the stage target file and endpoint are gone and the application job sees only dev. Also cover source removal.
   - **Stop:** do not accept until repeated sync removes stale app targets and preserves unrelated/runtime target files.
