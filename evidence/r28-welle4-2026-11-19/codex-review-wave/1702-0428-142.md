### 1. Blocking — `configured` is only manifest declaration, not backend evidence

`cmd/baha/app_status_result.go:76-84` says the witness is derived from manifest truth. The state `unreachable` is declared at `app_status_result.go:64-65` but has no emission path (`rg` found only its declaration). Thus the result does not provide the owner-defined second face, a per-signal backend witness. It reports manifest selection a second time under a backend-shaped label. This does not claim `healthy`, but it also cannot distinguish configured-and-backed from configured-without-backend-evidence.

**Recipe:** In `cmd/baha/app_status_result.go:76-139`, retain the manifest-side selection as a separate value and populate each backend's result from its own authoritative registration/witness input (Prometheus, Loki, Tempo independently). Do not add a live health probe or infer one backend from another. Emit `configured` only when that backend witness exists; emit `unreachable` only when the existing authoritative status path establishes that selected signal lacks its backend witness. If no such deterministic input exists, stop and report the missing source with file/line instead of relabeling manifest declaration as backend proof. Keep `cmd/baha/perses_lifecycle.go:217-233` and `app_status_result.go:243-250,351-353` on the same per-signal result.

**Test requirement:** Extend `cmd/baha/app_status_result_test.go` with independent Prometheus/Loki/Tempo cases that establish backend evidence and absence of backend evidence through a deterministic existing seam, asserting each backend separately. The absent-backend case must actually set up the no-witness condition; it must not merely assert an `unreachable` string. Include mixed-backend cases proving no cross-backend inference and check parity of the machine and human status faces.

**Stop criterion:** Stop if a backend's own witness cannot be sourced without inventing a probe or borrowing another backend's state. No `configured` backend result may pass with only its manifest declaration; no unreachable test may pass without setting up the missing-witness condition.

Remove or migrate the legacy `configured_unverified`/`verified` state surface instead of leaving it alongside the new witness.

**Test requirement:** Assert the complete serialized `baha app status --json` and `baha app perses status` status vocabulary for selected and unselected manifests; verify neither `healthy` nor `verified` occurs in a state value, including the legacy `perses` field.
