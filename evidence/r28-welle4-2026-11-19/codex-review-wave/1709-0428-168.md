## P1 — Production invocation exists, but the migrated registration is overwritten

The call is in production, not tests only: `localKeycloakRealization.Apply` calls `r.registerKeycloakSignals()` (`internal/identityprovider/keycloak_realization.go:66-117`, call at `:114`). That function calls `observability.ReconcileLegacySignals` before `RegisterProviderSignals` (`:162-194`, migration at `:173-183`, new registration at `:185-194`). So the migration function is genuinely on the Keycloak registration path.

However, the result does not preserve the old registration. `ReconcileLegacySignals` changes each matched legacy entry’s ID to the *current caller’s* `newID` and appends it (`internal/observability/migration.go:55-70`). Immediately afterward, `RegisterProviderSignals` removes every existing entry with that same `(registration.ID, provider)` pair and appends the current caller’s desired entry (`internal/observability/registry.go:250-260`). If the current caller has metrics disabled, the desired set is empty and the just-migrated entry is deleted; if enabled, it is replaced by the current caller’s registration and owner. The integration fixture explicitly uses a legacy source owned by `appA`, then registers a different Keycloak project/appB (`keycloak_legacy_migration_integration_test.go:31-65`), but after the operation it checks only that *some* Keycloak metrics signal exists at `newID` (`:69-83`); it never proves appA’s source survived. The implementation therefore does not establish the contract that the pre-existing source remains observable or is migrated as that source.

**Blocking recipe:** revise `internal/observability/migration.go:55-70` and its production integration in `internal/identityprovider/keycloak_realization.go:162-194` so the old source remains independently observable/removable under an identity derived from that old source, or is retained through an explicit compatibility listing/removal path. Do not move it to the current project ID and then overwrite it. Add an integration regression with a legacy appA source and a distinct appB registration, both metrics-enabled and metrics-disabled, asserting the old source’s owner and signal data remain visible/removable after appB registers. Stop if the old source is replaced by appB’s entry, disappears from appA’s list, or cannot be removed by its migrated identity.

## P2 — Idempotency, no mutation, and state locking

The implementation does use the existing registry lock: `mutate` opens `<registry>.lock` and takes `syscall.Flock(LOCK_EX)` around read/modify/write (`internal/observability/registry.go:707-747`). No new lock is introduced, so the lock discipline itself is correct.

The “no mutation” claim is not met. `ReconcileLegacySignals` always calls `mutate` (`migration.go:51-55`). `mutate` always marshals and writes a temporary file and renames it over the registry, even when the callback returned identical contents (`registry.go:724-747`). On an absent registry, the empty/no-legacy callback still writes `[]\n`; on an already migrated entry, the second call still replaces the file. `TestReconcileLegacySignalsIdempotentAndNoMutation` checks absence/presence and only compares entry count, ID, and OwnerApplication (`keycloak_legacy_migration_test.go:140-186`); it does not establish no file write and does not compare the complete source record. This differs from the cited pure migration precedent, where an unchanged input returns no changed entries and the caller skips persistence (`internal/deployment/target_id.go:67-80`).

**Blocking recipe:** add a change-aware path under the existing `mutate` lock in `internal/observability/registry.go:707-747` (or equivalent locked helper owned by this migration) that returns without writing when the registry did not change. Keep the existing lock; do not add a parallel migration lock. Extend `TestReconcileLegacySignalsIdempotentAndNoMutation` in `internal/observability/keycloak_legacy_migration_test.go` to cover an absent registry and an already-correct new ID, checking complete registry bytes and that the file was not replaced/rewritten on the no-op. Stop if either no-op path creates/replaces the registry file or changes any source field.
