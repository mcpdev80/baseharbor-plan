The returned maps are appended in precedence order: the caller’s canonical project (`:221`), recorded state-derived projects, then registry-derived projects for legacy holders without state. Thus a recorded owner retains its state mapping, while a legacy owner absent from the state tree can still resolve from the source of record.

The missing-root distinction is explicit in `ListKeycloakOwnerProjects` (`:414-439`): `os.IsNotExist` for the applications root means no retained state and returns `(nil, nil)` (`:416-420`); other root errors propagate (`:421`), and a per-owner read failure or empty environment directory returns an error (`:429-435`). `legacyLiteralOwners` propagates `observability.ListAll()` errors (`:333-337`) rather than treating a registry read failure as an empty owner set.

Before `RegisterProviderSignals` can mutate the registry, `ownerProjectMaps` calls `unresolvedLegacyOwners` and returns either its error or an explicit error listing unresolved owners (`:257-269`). The real registration path obtains this map before constructing and submitting the registration (`:182-205`). Therefore an unresolved or partially scanned owner aborts before the registry mutation; there is no half-migrated state from this path.
