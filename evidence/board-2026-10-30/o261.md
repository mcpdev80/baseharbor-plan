## Root cause

The podman-quadlet Targeted HA Route runs a fake exit-127 `docker` on PATH with `BASEHARBOR_TEST_RUNTIME=podman`, but ResolveDockerEngine ran the probe against docker subcommands (`context show` / `context inspect` / `--host info`) regardless of the configured runtime. On the podman runner `docker` is exit 127, so the preflight failed with `cannot resolve active Docker context; configure the Target's Docker endpoint or context` (Run 41110317467).

## Repo-rule compliance

- internal/runtime/docker_engine.go: `dockerEngineOutput` resolves the runner via `engineRunner(command, os.Getenv("BASEHARBOR_TEST_RUNTIME"))`; `resolveDockerEngine` resolves the runner once and passes `runner` to all three `run(…)` call sites instead of `command`.
- engineRunner returns `podman` when BASEHARBOR_TEST_RUNTIME equals podman (case-insensitive, trimmed); otherwise returns the original command unchanged. The docker path is byte-identical to pre-change behaviour, so the fail-closed Docker contract is preserved.
- Podman shares the docker CLI subcommands used here (`context show` / `context inspect` / `--host info`), so the same probe round-trips through podman.
- No consumer changed: ResolveDockerEngine signature, DockerEngineObservation, and all callers (docker/provider.go, cmd/baha/docker_engine.go) are untouched.
