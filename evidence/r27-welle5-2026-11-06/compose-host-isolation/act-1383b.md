## Review point 1 — per-test host isolation contract (contractually met)

The prior round-2 review (`789ae146`, review-1383b) REJECTED on two grounds:
(1) the bootstrap `BASEHARBOR_TARGET=w169-ci-bootstrap` selection leaked to
later lifecycle calls and could be a fallback; (2) the isolated ensemble +
mutant were never run. Head `1b02e88` closes (1) with commit `3fcba08f`:

- Bootstrap selection is now **scoped inside**
  `ensureRuntimeIntegrationTrustPlane`: it sets `BASEHARBOR_TARGET` to a fresh
  per-process bootstrap target, bootstraps the control-plane Core, and then
  **restores the neutralized selector** — `os.Unsetenv("BASEHARBOR_TARGET")`
  plus `mutatePersistedTarget("", true)` (which removes the persisted
  `active-target` file). So the bootstrap Core can no longer be the fallback for
  any later lifecycle call.
- Bootstrap target name is now a **per-process random suffix**
  (`bootstrapTargetSuffix()` via `crypto/rand`), so a contaminated/pre-existing
  fixed-name Core can never be the isolation boundary.
- Each lifecycle test keeps its own `isolateRuntimeForTest(t, name)` with a
  distinct `BASEHARBOR_TARGET=w169-<name>-iso`, configures its own fresh target,
  and asserts via a fail-closed scope proof that the resolved target is its own
  isolated Core — never the shared bootstrap nor the ambient `local` Core.
- `selectedTargetName` (target_selection.go) resolves explicit → `BASEHARBOR_TARGET`
  → persisted → default → single → conflict → implicit-local. With the
  neutralized selector restored after bootstrap, a later test without its own
  override resolves to the ambient `local` Core (the red gate), not to the
  bootstrap Core. This is the per-test discriminating proof the prior review asked
  for.

No mutual destruction: the ambient `local` Core and any foreign Core are never
reset, deleted, or disconnected. The shared daemon is only ever read. The
bootstrap target is a fresh per-process `<name>-default` network/Core.
