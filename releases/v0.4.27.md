# v0.4.27 · Remote development and onboarding

Source: [baseharbor#874](https://github.com/mcpdev80/baseharbor/issues/874). Tasks: [views/releases/v0.4.27.md](../views/releases/v0.4.27.md). Epic: [core-777](../epics/core-777-developer-access-and-profiles.md).

## Goal

Finish the end-to-end remote Node, Core/Target, authentication and developer profile experience without overloading the Console release.

## Work area 1 — Remote infrastructure

- Node Connector enrollment (`baha node add/connect`), token → mTLS, rotation, reconnect, offboarding and deterministic Core/Target ownership across multiple nodes.
- Core and remote Target selection, access, lifecycle and failure recovery; preserve existing #767/#768/#769/#846 work and fill only verified gaps.
- Owns connector/Core/remote transport and the shared authority domain; no Console UX files.

## Work area 2 — Developer onboarding and access (core-777)

- Local development without login; remote one-time connection bundle import/enrollment followed by normal work; shared/Test/Prod external or managed OIDC only when required.
- Import/export using the schema set in v0.4.25, secure optional credential portability, native auth reuse, multi-device, device/user/access removal, actionable wizards.
- Coordinate CLI registration through an owned integration seam; no duplicate Core/Target state authority; no Console feature-completeness promise.
- Owns developer access/profile and enrollment human/machine adapters, not connector internals.

## Acceptance

- Two real end-to-end Dev Local/Remote journeys, multiple Targets, mTLS rotation/offboarding and no-login local.
- Profile export/import and ownership protection verified.
- CLI/JSON/MCP state and authority parity, negative and lost-connection tests; EN/DE.
- Isolated PRs per area and exact-SHA integration/targeted runtime evidence. (The source says "two isolated PRs"; under the task-PR model this means at least one PR per cut task.)

## Ordering and boundaries

Depends on v0.4.26; Console usage follows in v0.4.28. Related: #777, #769, #846, #174. Candidate scope in triage: [nc-3](../tasks/nc-3-core-enrollment-remote-runtime-acceptance.md) matches work area 1 but has no release assignment in its source.

See [decisions/2026-10-15-task-prs-supersede-shared-release-prs.md](../decisions/2026-10-15-task-prs-supersede-shared-release-prs.md).
