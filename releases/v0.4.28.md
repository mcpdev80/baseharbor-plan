# v0.4.28 · CLI semantics and Grafana OSS

Source: [baseharbor#875](https://github.com/mcpdev80/baseharbor/issues/875). Tasks: [views/releases/v0.4.28.md](../views/releases/v0.4.28.md).

## Goal

Before WSL2 and macOS platform work, audit and harmonize the complete human CLI command model, including Target defaults, lifecycle scope, help and shell completion. Platform work must consume the accepted command contract.

Console and Node Connector repositories are archived snapshots and are outside this and future public release scope. v0.4.28 focuses on a consistent CLI before platform work and a complete optional Grafana OSS integration.

## First engineering priority — CI shard result reuse (critical)

- [Green Go shard reuse](../tasks/t-20261109-r27-ci-go-shard-reuse.md) is the first development task of v0.4.28, immediately after required cleanup and Renovate intake. Preserve its historical stable card number.
- Reuse authenticated, unaffected green CLI and package shard results across successive commits within one PR; rerun only the impacted tests and native gates with strict dependency/fixture/plan SHA verification.
- No new CI framework, evidence approval chain, or blanket full matrix; keep PR Selected Checks fail-closed on unknown, missing, failed or stale evidence.

## Inherited v0.4.27 follow-up scope (Owner decision 2026-11-13)

The ten unfinished implementation/extended qualification cards listed in [the v0.4.27 open-card audit](../evidence/v0.4.27-open-card-release-cut-2026-11-13.md) belong to this release. Existing stable `0427-xxx` card numbers remain unchanged by the cross-release move.

Scope includes dirty/untracked source delta, editable existing Target deployment policy with verified Core provenance, advanced rollouts/promotions, multi-workstation and external corporate OIDC acceptance, GitHub/GitLab consumption examples, and extended Demo stage-version proof. Connector-specific delivery is excluded. Coordinator must check current code and prior receipts first; the cards remain unaccepted and are not parallelized across conflicting files. Prioritize the first release's actual acceptance before starting optional implementation.

## Work area — CLI command semantics

- Inventory all human commands, clarify resource and Target scope, align defaults and lifecycle names, and update generated help and shell completion.
- Preserve local and remote operation, safety gates, machine-interface semantics and EN/DE guidance.
- Complete this work before the WSL2 and macOS implementation tasks in v0.4.29.

## Binding scope expansion — Grafana OSS (Owner decision 2026-11-13)

The **complete Grafana OSS visualization integration** (historical candidate #166) is part of v0.4.28, **not post-v0.5**. This replaces and removes all Grafana deferral language from `core-209`. Delivery includes optional managed installation and lifecycle, secure access, provisioned Prometheus/Loki/Tempo data sources, real monitoring dashboards, native Grafana OSS alerting/routing, end-to-end Docker and rootless Podman tests, and EN/DE documentation. Grafana remains optional per installation and is never an implied application capability or a mandatory dependency of minimal deployments. A complete integration is required when enabled, not merely a static link, demo, or partial dashboard.

Monitoring must distinguish available telemetry from absent collection. Use existing metrics/logs/traces and provider ownership; do not create a parallel telemetry/monitoring database or collector. Grafana alerts must be real, bounded and provisioned through supported OSS APIs, with tenant/Target scope and secret-safe contact points; no invented alert coverage or unapproved external notification service.

The small new task slices are:
- [0428-010](../tasks/t-20261113-r28-grafana-runtime.md) optional Grafana runtime.
- [0428-011](../tasks/t-20261113-r28-grafana-datasources.md) live Prometheus/Loki/Tempo provisioning.
- [0428-012](../tasks/t-20261113-r28-grafana-dashboards.md) real dashboards.
- [0428-013](../tasks/t-20261113-r28-grafana-secure-access.md) protected Grafana access.
- [0428-020](../tasks/t-20261113-r28-grafana-alerts.md) OSS alert rules (contact routing is separate 0428-031).
- [0428-043](../tasks/t-20261114-r28-cli-command-semantics.md) human CLI command and lifecycle semantics before platform work.

**Execution authority:** one Coordinator schedules at most five independent Workers for genuinely dependency-ready tasks with disjoint file ownership. Each worker claims and hands off one scoped implementation PR. **Codex independently reviews and merges** only after exact-HEAD required checks and actual assertions; Coordinator reconciles planning, then schedules successors. No worker merges or releases. Reuse code and accepted 0.4.24–0.4.27 behavior; inspect Console PR #8 before editing overlapping tests. Do not recreate already delivered architecture.

## Provider Contract and dashboard dependency rules (binding)

- **0428-032 is the Grafana architecture gate:** `IntegrationDescriptor.Validate` currently requires a real application capability, so Grafana MUST be modeled as an optional provider-owned management/visualization tool through a compatible Provider Contract v1 extension or existing management interface; never falsely implement `metrics`, `logs`, `traces`, or change portable application intent.
- **0428-033 inventories actual produced/collected series, labels and provider ownership** before dashboard or alert selection. An installed provider is not evidence that an exporter or all required metrics exist.
- **0428-034 chooses dashboard templates only when their real query prerequisites are satisfied** by authorized selected Target/provider instances. Existing community templates are curated sources, not auto-enabled, authoritative or guaranteed to work unchanged.
- Verified candidates: [Node Exporter Full 1860](https://grafana.com/grafana/dashboards/1860-node-exporter-full/) (requires Node Exporter), [Docker monitoring 15798](https://grafana.com/grafana/dashboards/15798-docker-monitoring/) (requires cAdvisor metric and label compatibility), [PostgreSQL 9628](https://grafana.com/grafana/dashboards/9628-postgresql-database/) (requires postgres_exporter), [MongoDB Replica Set 25802](https://grafana.com/grafana/dashboards/25802-mongodb-replica-set-full-overview/) (requires Percona mongodb_exporter and matching metrics), [RabbitMQ Overview 10991](https://grafana.com/grafana/dashboards/10991-rabbitmq-overview/) (requires RabbitMQ Prometheus plugin-compatible data). All are **conditional**; do not add privileged exporters or show empty dashboards as deployed/healthy.
- **0428-035, 036, 037** are independently writable host/container, database and messaging template tasks after 034. Existing native BaseHarbor infrastructure dashboard 012 and logs/traces dashboard 024 use real signals. Dashboard JSON/import version/UIDs must be pinned, tested, and scoped to existing metrics/logs/traces.
- **Do not over-serialize:** Provider Contract (032) and current metric inventory (033) can run independently after release start. Grafana runtime (010) depends on 032. Grafana datasource workers 011/022/023 can then work in parallel in disjoint files; dashboard and security workers can proceed on their actual prerequisites. Grafana native proof (030) remains separate. One Coordinator schedules up to five non-overlapping workers; Codex reviews and merges.
- Each card explicitly identifies exact source entry points or requires the worker to inspect current source and stop on a missing contract. Preserve targeted CI routing and exact-SHA evidence.

### Additional granular Grafana tasks

- 0428-021 Grafana lifecycle, 022 Loki source, 023 Tempo source, 024 logs/traces dashboard.
- 0428-030 Grafana native proof; 031 Grafana OSS notification contacts/routing.
- **0428-032 Provider Contract v1 architectural gate**; 033 actual metrics/label inventory; 034 conditional dashboard template selector.
- 0428-035 host/container dashboards; 036 PostgreSQL/MongoDB; 037 RabbitMQ; 038 Valkey; 039 Keycloak. All tied to verified source/provider support, not blindly deployed.

Grafana dashboards have strict eligibility checks: no exporter present means dashboard not offered as operational; no anonymous high-privilege collector, no unapproved data expansion. Existing [Redis exporter dashboard 763](https://grafana.com/grafana/dashboards/763-redis-dashboard-for-prometheus-redis-exporter-1-x/) is a conditional Valkey starting point; legacy [Keycloak dashboard 10441](https://grafana.com/grafana/dashboards/10441-keycloak-metrics-dashboard/) requires historical Metrics SPI and must not be installed blindly on current Keycloak.
