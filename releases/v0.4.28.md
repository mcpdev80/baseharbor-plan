# v0.4.28 · Console and management workflows

Source: [baseharbor#875](https://github.com/mcpdev80/baseharbor/issues/875). Tasks: [views/releases/v0.4.28.md](../views/releases/v0.4.28.md).

## Goal

Deliver genuinely usable Console journeys, not only a login or a working UI container. The Console stays an optional client of one selected management Core, never a second authority.

## First engineering priority — CI shard result reuse (critical)

- [Green Go shard reuse](../tasks/t-20261109-r27-ci-go-shard-reuse.md) is the first development task of v0.4.28, immediately after required cleanup and Renovate intake and **before** Console implementation. Preserve its historical stable card number.
- Reuse authenticated, unaffected green CLI and package shard results across successive commits within one PR; rerun only the impacted tests and native gates with strict dependency/fixture/plan SHA verification.
- No new CI framework, evidence approval chain, or blanket full matrix; keep PR Selected Checks fail-closed on unknown, missing, failed or stale evidence.

## Work area 1 — Console backend and domain integration

- Authenticated one-Core connection, proper RBAC/ownership and the shared Core/Target application API.
- Expose all permitted visible local/remote Targets; application lifecycle, logs/events, status/doctor, safe mutation and useful evidence through existing Core/domain interfaces.
- Bridge core-777 onboarding/authorization with the Console; no duplicate provider or Target state.
- Owns Console backend/API integration and server-side adapters.

## Work area 2 — Console frontend and UX acceptance

- Guided app create/edit with the same capability checklist/compact footprint preview as the CLI.
- Target selection, repository/workspace management where supported, app operations, logs/events, actionable failures and verification.
- Full independent login → choose Core/Target → deploy/edit/inspect → remove/offboard journey; EN/DE docs.
- Owns Console UI and web UX tests, not backend authority.

## Acceptance

- Real Console journey including remote Target and Core boundaries; parity with CLI/MCP on supported semantics.
- Secure login/access, safe negative paths, no secret leak, no phantom functionality.
- Explicit pre-freeze decision on the Console AI assistant: define a read-only/tool boundary or defer the feature past v0.5; do not silently omit it.
- Isolated PRs per area, integrated exact SHA, focused QA and docs.
