# v0.4.28 · CLI semantics and Perses

Source: [baseharbor#875](https://github.com/mcpdev80/baseharbor/issues/875). Tasks: [views/releases/v0.4.28.md](../views/releases/v0.4.28.md).

## Goal

Before WSL2 and macOS platform work, audit and harmonize the complete human CLI command model, including Target defaults, lifecycle scope, help and shell completion. Platform work must consume the accepted command contract.

Console and Node Connector repositories are archived snapshots and are outside this and future public release scope. v0.4.28 focuses on a consistent CLI before platform work and a complete optional Perses visualization integration.

## CI shard reuse status

[Green Go shard reuse](../tasks/t-20261109-r27-ci-go-shard-reuse.md) was closed by [explicit Owner direction](../decisions/2026-11-14-owner-close-inherited-work.md), which records the Owner's statement rather than independently reproduced CI evidence. It is no longer an open release-start implementation task. Existing CI safety and actual release qualification requirements continue to apply.

## Inherited v0.4.27 follow-up scope (Owner decision 2026-11-13)

The inherited implementation/extended qualification cards originally listed in [the v0.4.27 open-card audit](../evidence/v0.4.27-open-card-release-cut-2026-11-13.md) belong to this release. Existing stable `0427-xxx` card numbers remain unchanged by the cross-release move.

Scope includes dirty/untracked source delta, editable existing Target deployment policy with verified Core provenance, advanced rollouts/promotions, multi-workstation and external corporate OIDC acceptance, GitHub/GitLab consumption examples, and extended Demo stage-version proof. Connector-specific delivery is excluded. Coordinator must check current code and prior receipts first; check each card’s current status and do not parallelize conflicting files. Prioritize the first release's actual acceptance before starting optional implementation.

## Work area — CLI command semantics

- Inventory all human commands, clarify resource and Target scope, align defaults and lifecycle names, and update generated help and shell completion.
- Preserve local and remote operation, safety gates, machine-interface semantics and EN/DE guidance.
- Complete this work before the WSL2 and macOS implementation tasks in v0.4.29.

## Binding observability scope — Perses (Owner decision 2026-11-14)

[Owner decision](../decisions/2026-11-14-perses-replaces-grafana-v0428.md): replace the planned Grafana dashboard UI integration with optional **Perses**. Previous Grafana cards are closed as superseded and point to specific Perses successors; historical records remain. The existing Prometheus, Loki and Tempo data backends are independent and are not removed by this decision. Perses integration must use a reviewed pinned version and actually available Prometheus/Loki/Tempo plugins, supported native provisioning and secure scoped access. No claim of current implementation or blanket compatibility with Grafana dashboards.

Existing real-signal inventory and conditional dashboards remain required, with no invented series, implicit privileged exporters or parallel monitoring database. Alert evaluation and notification delivery must be defined on a real supported Prometheus/Alertmanager or other approved architecture; an Alertmanager plugin does not establish full rule-management or routing support. Notifications remain opt-in and secret-safe.

A coordinator can schedule up to five independently owned workers when each card’s technical prerequisites are accepted, including while release startup waits. Codex acting under Owner delegation reviews exact-SHA results and merges only after actual required checks; do not claim independent review or native proof without evidence. The public Console and Node Connector repositories remain archived and out of release implementation and qualification.

Start the five independent CLI audits or combine scheduling with the independent Perses provider-seam and signal-inventory tasks, according to available ownership; never exceed five. 4. ## Acceptance

- Full CLI command inventory with clear Target and lifecycle semantics, consistent active-Target selection/completion, and local/remote parity.
- Matching EN/DE help and docs with parser/help and safety regressions routed through CI.
- Perses remains optional, displays only actually collected authorized signals, and passes applicable Docker and rootless Podman lifecycle, access and dashboard tests. Any alerting and routing claims require a separately implemented and verified evaluator and notification owner.
- Isolated PRs per area, integrated exact SHA, focused QA and docs.
